# Tactile encoders

The six encoder methods are `ResNet`, `VAE`, `MAE`, `DINOv2`, `I-JEPA`, and `V-JEPA`. Each method has its own `model.py`, `train.py`, and S/B training configuration. ResNet-S is the CNN ResNet18; ResNet-B is Wide ResNet50-2. Other methods use ViT-S/B with 16×16 patches on 224×224 inputs.

| Method | Training forward | ACT `cls` | ACT `full` |
| --- | --- | --- | --- |
| ResNet | CNN spatial map → pooled 512-dimensional vector → image decoder; same-input pixel MSE | 1 × 512 | 64 spatial tokens on ACT's 256×256 input, 512 (S) or 2048 (B) channels |
| VAE | ViT 196 patches → learned residual 3×3 stride-2 convolution → 49 latent means/log variances → sampled 49 latents → learned residual 7×7-to-14×14 upsampling → 196 reconstructed image patches; pixel MSE + KL | Mean of 49 latent means, 1 × 384/768 | 49 latent means, 7×7 × 384/768 |
| MAE | Mask 75% of 196 patches → encode 49 visible patches plus CLS → decoder reconstructs masked pixels | Unmasked CLS, 1 × 384/768 | Unmasked CLS + 196 patches, 197 × 384/768 |
| DINOv2 | Two global and one local student views, two global EMA teacher views; CLS distillation, masked-patch iBOT-style distillation, and KoLeo feature regularization | CLS, 1 × 384/768 | CLS + 196 patches, 197 × 384/768 |
| I-JEPA | Single image, two non-overlapping 6×6 target blocks; context encoder sees 124 visible patches and predicts the other 72 with an EMA teacher; the context embedding also receives a Gaussian SIGReg constraint | Mean of 196 patch tokens, 1 × 384/768 | 196 patch tokens, 14×14 × 384/768 |
| V-JEPA | Current-frame ViT context encoder predicts the next-frame EMA target CLS latent conditioned on the next absolute 8D joint target; LeWM-style SIGReg regularizes the projected context latent | Projected CLS, 1 × 384/768 | 196 spatial patch tokens, 14×14 × 384/768 |

All four input modes have three channels. `marker_only` renders the first 63 current marker positions as radius-2 white dots on a black canvas, scales coordinates from 320×240 to the requested image size (224×224 by default), and copies the same raster into R, G, and B (`R = G = B`). It returns a float32 tensor of shape `[3, H, W]` in `[0, 1]`; repeating the channels adds no new marker information. Encoder pretraining and policy data loading use the same representation. Existing one-channel `marker_only` encoder checkpoints require retraining or explicit weight conversion before use with this input. The first three methods reconstruct the selected input mode; for sparse `marker_only` images, foreground pixels receive 50× additional weight in the reconstruction MSE to avoid a blank-image solution. DINOv2, I-JEPA, and V-JEPA use feature-learning objectives. `depth_deform` stores normalized depth in R as `clip((34 - camera_depth_mm) / 10, 0, 1)`: the 34 mm no-contact baseline maps to zero and decreasing camera distance increases R. G/B store interpolated x/y marker displacement as `clip(displacement_px / 40 + 0.5, 0, 1)`. `depth_marker_to_deform.py` provides the standalone conversion CLI. The historical ResNet18 checkpoint format is still accepted by ACT.

The displacement field uses linear interpolation inside the marker convex hull. Outside it, the eight nearest markers contribute with normalized inverse-square-distance weights, so nearby markers contribute more than distant ones.

```bash
./train_encoder.sh --method VAE --size S --input marker_rgb
ENCODER_METHOD=VAE ENCODER_SIZE=S INPUT_MODE=marker_rgb TACTILE_TYPE=full ./train_policy.sh
```

Use `TACTILE_TYPE=cls` for one token, or `full` for all method-specific tokens. `train_encoder.sh` loads batch size, learning rate, epochs, and method options from that method's `config.yml`; overrides follow `--`, for example `-- --epochs 1 --max-steps 2`. One A100 GPU is used by default; set `CUDA_VISIBLE_DEVICES` to choose a card. The default training budget is 100,000 tactile frames, split 80/20 by HDF5 trajectory file with seed 42. The same file split is used across model settings; validation is run after each epoch. Reconstruction methods select the lowest-validation-loss encoder. Self-distillation methods can select by frozen-encoder kNN accuracy on held-out object shapes, using labels only for checkpoint selection and never for pretraining gradients. The selected encoder is `encoder.pth`, while `last.pth` retains the latest full training state. A run is saved under `encoder_results/<input_mode>/<method>/<size>/<timestamp>/`, containing checkpoints, `metrics.jsonl`, `config.json` with the exact file split, and `train.log`. All run IDs are timestamps. Historical ResNet18 pretraining uses the same directory layout, with its legacy checkpoint format and sample count recorded in `config.json`. `train_policy.sh` selects the latest matching encoder checkpoint unless `ENCODER_CKPT` is set. Historical ablation files are archived outside `encoder_results` in `archive/encoder_ablation/` and are not used for policy checkpoint selection.

The training configs use batch size 64 on one A100 per run, so two independent runs can occupy the two cards. A fixed 8,192-frame, 3-epoch pilot compared batches 64, 256, and 512 across all ten method/size pairs on `marker_rgb`. Batch 64 had the best validation result for every pair; larger batches gave only a small wall-clock speed benefit at equal epochs, and DINOv2-B at 512 ran out of memory. The model-specific epoch limits and early stopping are in each `config.yml`. Smoke runs verify execution and memory, not convergence or downstream policy quality.

I-JEPA adds LeWM/LeJEPA-style sketched isotropic Gaussian regularization (SIGReg) to a learned projection of the pooled context tokens. Each step compares random one-dimensional projections of the image batch against a standard normal distribution using an Epps–Pulley characteristic-function statistic. The existing masked latent prediction and EMA teacher remain in place. Its configuration controls the SIGReg weight, projection dimension, and number of random projections; validation logs include `val_sigreg`, projected feature standard deviation, and teacher feature standard deviation to detect collapse.

V-JEPA predicts one frame ahead (`future_horizon: 1`), following LeWM's next-embedding objective. HDF5 files contain `embodiment/joint` rather than a separate `/action` array, so the action condition follows this repository's ACT convention: the absolute joint target at `t+1`, columns `:8`. Action normalization uses training trajectories only. The student and future-frame EMA target share a ViT-S/B encoder architecture with a BatchNorm projector; the LeWM-style objective is latent MSE plus SIGReg with weight 0.09. The EMA target is retained as requested, although official LeWM itself uses a single encoder without an EMA teacher. `encoder/V-JEPA/config.yml` stores one tuned learning rate per size.

For repeated training on the bundled contact data, `scripts/build_encoder_manifest.py` creates `encoder_results/.contact_lengths.json` with HDF5 frame counts. Training uses that index when its file list matches; rebuild it after changing the source HDF5 files. `scripts/run_encoder_grid.py` runs the 48 method/size/input smoke combinations, and `scripts/tune_encoder.py` compares learning rates and batches on the fixed file split.
